## 다음 (착수 전, 우선순위 순)

### 1. 다른 회사 DB 에 붙이는 절차

스키마 카드, 레인 도구 설명에 적은 표와 문서와 관계 목록, 카탈로그 주석 초안 생성기(`npm run companyx:comments-draft`)가 지금은 Company-X 데이터셋에 맞춰져 있다. 다른 데이터베이스에 붙이는 길을 보여 준 적이 없다.

- 하는 일: 초안 생성기를 어느 PostgreSQL 데이터베이스에서나 돌게 한다(information_schema 와 pg_stats 로 표와 열마다 주석 초안을 쓴다). 초안 생성, 담당자 검수, 연결의 세 단계를 문서 한 장으로 쓴다. 사업자 데이터셋이 아닌 공개 예제 DB 로 처음부터 끝까지 따라 해 본다.
- 완료 판정: 그 문서만 보고 다른 DB 에 붙인다. 질문 하나가 조회한 행과 함께 답하는 것을 기록으로 남긴다.

### 2. NL2SQL: 정형 레인의 상한

봉인 홀드아웃5 에서 라우팅이 맞은 정형 17문항 가운데 답이 맞은 것은 11이다. 7B 가 쓴 SQL 의 실행 일치는 10/20 이다(`docs/report.md` §0.18). 문서 18/20, 그래프 16/17 보다 낮다. 정형 레인의 상한이 여기서 정해진다.

- 하는 일: 홀드아웃5 정형 20문항(채점이 끝나 이제 개발용이다)의 오답을 문항마다 어느 단계에서 틀렸는지(없는 열이나 틀린 표, 조인, 필터, 집계, 값 표기) 적는다. 생성 모델 교체도 같은 규약으로 잰다. 2026-09-30 에 잰 두 후보(qwen3.5:9b, gemma4:e4b)는 미리 정한 교체 기준(+3)에 못 미쳤다(§0.15). 그 뒤 나온 오픈웨이트 코드 모델도 같은 문항으로 잰다.
- 완료 판정: 고친 판을 처음 보는 봉인 세트(홀드아웃6)로 한 번 잰다. 채택 기준은 채점 전에 PR 에 적는다.

### 3. 네트워크 전송의 인증

SSE 와 Streamable HTTP 는 기본으로 127.0.0.1 에만 붙고 브라우저 Origin 을 검사한다. 인증은 없다. 지금은 한 사람이 자기 기기에서 stdio 로 쓰는 것을 전제로 한다. 감사 레코드의 호출 주체도 stdio 일 때만 OS 계정을 적는다.

- 하는 일: 여러 사람이 함께 쓸 때의 배포 절차를 쓴다. 서버를 인증하는 리버스 프록시 뒤에 두고, 프록시가 넘긴 사용자를 감사 레코드의 `caller` 에 싣는다. air 가 MCP 규격의 권한 부여를 지원하면 그쪽을 쓴다.
- 완료 판정: 인증 없이 온 원격 요청이 거절되고, 인증된 요청의 감사 레코드에 사용자가 남는 것을 테스트로 확인한다.

### 4. air 보안 레이어(Shield)

air 0.4 부터 정책, 위협 탐지(프롬프트 인젝션, 경로 이탈, 명령 주입 패턴), 호출 한도, 감사를 한 미들웨어로 준다. 출품작 기능검증(2026-10-19) 전에는 시험항목 화면이 바뀌어 켜지 않았다. 남은 걸림은 감사 로그다. 허용한 호출까지 메모리 배열에 상한 없이 쌓는다(`audit: false` 로 끌 수 있다. 감사는 우리 감사 레코드가 한다). 거절 응답의 `isError` 는 PR #5 패치로 클라이언트까지 간다.

- 하는 일: 감사를 끄고 위협 탐지와 호출 한도만 켠 판으로 시험항목 187건과 평가 세트를 다시 돌린다. 막히는 정상 질문이 있는지 본다.
- 완료 판정: 정상 질문 차단 0, 패턴에 걸리는 입력(인젝션 문장, 경로 이탈)은 `isError` 와 사유를 단 응답으로 거절된다.

### 5. 도구가 늘어날 때의 라우팅

규칙 라우터는 도구 8개와 레인 셋을 전제로 짰다. 셋째 단계도 만들었다. 규칙과 임베딩이 둘 다 확신하지 못하는 질문을 7B 가 레인 도구 설명을 읽고 고른다. 봉인 홀드아웃5 에서 라우터와 같은 56/60 이라 기본으로 꺼 두었다(켜려면 `ROUTER_LLM_STAGE=1`, §0.18).

- 하는 일: 다른 DB 나 쓰기 계층이 붙으면 도구가 열 개를 넘는다. 그런 구성이 생기면 레인 아래로 도구를 묶는 게이트웨이와 셋째 단계를 그 구성에서 다시 잰다.
- 완료 판정: 그 구성의 봉인 세트에서 셋째 단계가 규칙과 임베딩만 쓴 라우터보다 앞설 때 기본값으로 켠다.

### 6. 다국어 공식 768 임베딩 대조

앞 768 절단은 모델 카드가 보증한 출력 모드가 아니다(측정상 손실은 관측되지 않았다). 다국어이면서 공식적으로 768을 내는 모델을 확보하면 같은 68문항으로 대조하고, 통과 기준(nDCG@5 신뢰구간 하한이 현행 대비 -0.03 이내)을 넘을 때만 교체한다. 영어 전용 768 모델은 같은 한국어 문항에서 25/68이라 대안이 아니다.

0.344(08-18 재추론)로 6.3pp 움직였다. 시스템이 좋아진 것인지 표본이 작아 흔들린

  **표집 오차가 0이므로 「이 표본으로는 가를 수 없다」가 더 이상 적용되지 않는다.**

  채점 가능분만 보면 43.8% 다.

  아래 판정문은 **지우지 않는다** — 무엇을 요구했고 무엇으로 충족했는지가 기록이다.

## 범위 밖 (하지 않기로 한 것)

- **자동 장애 조치(failover)**: 읽기 엔드포인트의 replica 폴백까지가 이 프로젝트의 범위다. 자동 승격과 lag SLA는 운영 HA 제품의 영역이고, 검증 없이 있다고 적지 않는다.
- **외부 상용 API 연동**: 이 프로젝트는 온프렘을 전제로 한다. 성능을 위해 외부 모델을 붙이는 선택지는 열지 않는다.
- **채점한 문항에 맞춘 튜닝**: 봉인 홀드아웃은 결과를 본 뒤 규칙, 앵커, 라벨을 고치지 않는다. 고치면 그 세트는 개발용이 된다. 고친 판은 다음 봉인 세트로 잰다. 사업자 공개 30문항의 남은 오답도 원인만 공개하고 그 문항에 맞춰 고치지 않는다.

air 0.2.0 과 0.3.0)는 air 0.5 가 선언한 인자를 목록에 싣고 받은 인자를 핸들러에 넘기면서 풀렸다. 그 우회였던
`promptargs.ts`(SDK 의 `prompt()` 감싸기)와 설명 끝의 `[인자] ...` 는 지웠다. 빈 필수 인자를 거절하는 것은 우리 규칙이라
`prompts.ts` 에 남는다. `node scripts/verify-prompt-arguments.mjs` 가 목록의 인자를 계속 대조한다.

우회로를 여기 적어 두는 이유는 분명하다 — **임시 조치를 영구화하는 가장 흔한 방법이
적지 않는 것이다.**
