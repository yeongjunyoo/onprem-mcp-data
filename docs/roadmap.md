## 다음 (착수 전, 우선순위 순)

### 1. 홀드아웃 3차 — 표면형 계열 확장

홀드아웃 1차(템플릿 문형)와 2차(구어체)는 각각 라우터 결함을 **진단하는 데 썼으므로 더 이상 홀드아웃이 아니다**(PR #14, #15). 구어체 strict 0.633이 현재 정직한 상한이고, 이 수치가 재현되는지는 라우터가 보지 않은 새 표면형 계열로만 확인할 수 있다.

3차에서 볼 것: 오탈자·축약·복합 질문(한 문장에 두 레인), 그리고 존재하지 않는 개체를 섞은 환각 유도 문항.

### 2. 다국어 공식 768 임베딩 대조

앞 768 절단은 모델 카드가 보증한 출력 모드가 아니다(측정상 손실은 관측되지 않았다). 다국어이면서 공식적으로 768을 내는 모델을 확보하면 같은 68문항으로 대조하고, 통과 기준(nDCG@5 신뢰구간 하한이 현행 대비 -0.03 이내)을 넘을 때만 교체한다. 영어 전용 768 모델은 같은 한국어 문항에서 25/68이라 대안이 아니다.

### 3. 키워드 레인 추가와 하이브리드 융합

현재 semantic 레인은 dense 벡터만 쓴다. 고유명사와 코드 문자열처럼 어휘가 정확히 일치해야 하는 질의는 dense가 약하다. PostgreSQL 전문검색 또는 2-gram 인덱스로 키워드 레인을 만들어 RRF에 네 번째 소스로 넣는다. 한국어 형태소 분석기는 확장 설치가 필요하므로 도입 전에 배포 환경 제약을 먼저 확인한다.

### 4. NL2SQL 평가 확장

현재 SQL 채점 문항은 10개다. 정답 SQL을 직접 작성해 문항을 늘리고, 실패 유형(존재하지 않는 컬럼 환각, 조인 누락, 필터 과잉)을 분류해 어디를 고쳐야 하는지 데이터로 말한다.

### 5. BIRD 표본 확대 — 32문항으로는 못 가르던 것 (✅ 2026-08-19 전수로 해결)

2026-08-18 재측정에서 **같은 32문항**의 공식 set 동등이 0.281(06-30 예측) → <!--metric-ok-->
0.344(08-18 재추론)로 6.3pp 움직였다. 시스템이 좋아진 것인지 표본이 작아 흔들린
것인지 **이 표본으로는 가를 수 없었다.**

- **✅ 완료 (2026-08-19) — 판정 ① 로 충족.** Mini-Dev **500문항 전수**를 돌렸다
  (stride=1, **11/11 DB**, 난이도 148/250/102
  — 공식 구성 30/50/20 과 같다). 생성 모델은 `qwen2.5-coder:7b`.
  공식 set 동등 **243/500 = 0.486**,
  운영 multiset 동등 **219/500 = 0.438**.
  **표집 오차가 0이므로 「이 표본으로는 가를 수 없다」가 더 이상 적용되지 않는다.**

  다만 **한계가 사라진 게 아니라 종류가 바뀌었다.** gold SQL 2건
  (q518, q701)이 하네스의 30초 실행 한도를 넘겨
  **채점 불가**다. 둘 다 정상 질의이고 느릴 뿐이다(101.6초 / 240초에도 미완료).
  헤드라인 43.6% 는 BIRD 관행대로 그 2건을 오답으로 세고,
  채점 가능분만 보면 43.8% 다.

  아래 판정문은 **지우지 않는다** — 무엇을 요구했고 무엇으로 충족했는지가 기록이다.

- 하는 일: stride 표집을 버리고 Mini-Dev 500문항 전량 또는 층화 표집으로 바꾼다.
  11개 DB 가 모두 들어가고 난이도 구성이 공식(30/50/20)에 맞아야 한다.
- 완료 판정: **둘 중 하나.** ① Mini-Dev **500문항 전수** — 표집 오차가 0이므로 추가
  조건이 없다. ② 층화 표집이면 **비율의 95% 신뢰구간 반폭이 ±5pp 이내**여야 한다.
  현재 n=32 로는 반폭이 약 ±16pp 라 통과할 수 없고, n≈370 부터 만족한다 —
  즉 **표본을 실제로 늘려야만 통과하는 조건**이다.

  앞선 두 판은 틀렸다. "같은 표본을 두 번 돌려 ±2pp" 는 재추론 변동을 재는 것이라
  **이미 만족돼 있었고**, "서로 다른 두 표본이 ±2pp" 는 **작은 표본이 우연히 일치**
  할 수도 대표성 있는 두 절반이 정당하게 벌어질 수도 있다. 판정을 적는 것과 그
  판정이 성립하는 것은 다르다.
- 전제: `sqlite3` CLI. 없으면 평가가 시작 전에 멈춘다.

### 6. 재측정 비용 낮추기

증거가 낡는 것은 도구로 잡게 됐지만(`evidence-manifest` 가 나이를 출력하고 30일을
넘기면 실패한다) **다시 재는 일 자체는 여전히 비싸다. 비싸면 미루고, 미루면 낡는다.**

### 7. 승인형 쓰기 도구

지금은 전 경로가 읽기 전용이다. 쓰기가 필요한 사용 사례는 실행 전 사람 승인을 요구하는 별도 계층으로만 연다. 읽기 전용 가드를 우회하는 방식으로는 만들지 않는다.

## 범위 밖 (하지 않기로 한 것)

- **자동 장애 조치(failover)**: 읽기 엔드포인트의 replica 폴백까지가 이 프로젝트의 범위다. 자동 승격과 lag SLA는 운영 HA 제품의 영역이고, 검증 없이 있다고 적지 않는다.
- **외부 상용 API 연동**: 온프렘 전제가 이 프로젝트의 정의다. 성능을 위해 외부 모델을 붙이는 선택지는 열지 않는다.
- **공개 문항에 맞춘 프롬프트 튜닝**: 남은 오답 3건은 원인을 공개했다. 여기서 더 손대면 30문항 과적합이 된다.

### 상류(upstream)에 열려 있는 것

> 추적: [#139](https://github.com/yeongjunyoo/onprem-mcp-data/issues/139) (`bug` · `good first issue` · `help wanted`)

**프레임워크가 프롬프트 인자를 MCP 목록에 싣지 않는다.** `@airmcp-dev/core` 가
MCP SDK 의 deprecated 오버로드를 쓴다.

```js
// server-runner.js
server.prompt(prompt.name, prompt.description || "", handler)
```

SDK 문서: *"Registers a **zero-argument** prompt ... @deprecated Use `registerPrompt`
instead."* 인자를 받는 오버로드가 따로 있는데 안 쓴다. 결과적으로 우리가 정의한
`question`·`context` 같은 인자가 `prompts/list` 에서 **빈 배열**로 나가고, 클라이언트는
템플릿의 어느 자리를 채울지 알 수 없다.

- **재현**: `node scripts/verify-prompt-arguments.mjs` — 정의한 인자와 목록을 대조한다.
- **확인 범위**: 0.2.0 과 0.3.0 둘 다 같다(2026-08-17).
- **현재 우리 대응**: 설명 문자열 끝에 `[인자] name(필수): 설명` 을 붙이는 **우회**다.
  검사는 `arguments` 또는 설명 둘 중 하나로 전달되면 통과하므로, 상류가 고쳐지면
  그것도 통과하고 **우회로를 지울 수 있다.**

우회로를 여기 적어 두는 이유는 분명하다 — **임시 조치를 영구화하는 가장 흔한 방법이
적지 않는 것이다.**
